# D-003 阶段A使用新夹具，而不是交接包的 example-project.json

- 状态：已采用
- 日期：2026-11-25

## 背景

交接包的 `example-project.json` 适合验证 Schema，但不适合阶段A的理解测试：

- 只有3个研究单元、1条证据，不足以支撑方案 §16.4 要求的“至少6个具有方法与证据差异的节点”。
- 研究单元的问题是模板拼接的（例如“验证校准是否提高最终任务完成率是否满足本阶段需求？”），三个单元的下一步都是“查验现有证据并开展当前节点对应工作。”，不符合方案自己的阅读规范 C03、C08。
- 实验运行的 `missing_fields` 写的是一句说明，而配置与环境引用又都已填写，和“缺项要明确列出”的含义不一致。

## 决定

新写一个夹具生成器 `fixtures/stage-a/build.ts`，用同一个虚构研究问题（车辆位置预测误差下的移动群智感知任务分配）生成一个更完整的项目：

- 4条路线（主线B、路线A、路线C、已关闭的复杂网络备选），9个研究单元，7条主张（含证据混合、未评估、论文陈述缺证据），6条证据，6项决定（含已被替代、待决定），4个候选（含模型建议、已按授权自动应用、前提会变化的建议），5条审阅（含旧版本审阅），1个部分可恢复的快照，2个会话绑定，2份能力清单，3项授权（含已过期），9份阅读说明，28个事件节选。
- 刻意包含需要被界面正确呈现的情形：执行失败不是反证；进程成功不改变主张；模型声称“重新训练”与实际文件不一致；推断关联与精确来源；同一符号 T 的两种含义；从旧快照继续时带上后来的反证。
- 生成后按合同 `domain.schema.json` 校验，并做跨对象检查（`npm run fixtures`）。合同原有的 `example-project.json` 保持不变。

所有内容为虚构，文件中和界面上都有说明。
