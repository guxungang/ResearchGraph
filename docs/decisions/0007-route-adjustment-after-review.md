# D-007 外部审查后的路线调整：先修正确性，再用真实会话检验，然后做阶段B

- 状态：已采用（研究负责人选择先做第1步；第1步已于 2026-11-26 完成，第2–4步的顺序待确认）
- 日期：2026-11-26
- 相关：方案“实施阶段”表与其后的说明（“不能用大量没有界面的基础设施代替用户闭环”；工期在“完成样机与一个真实连接器后”再估）、D-002、D-006

## 背景

另一个 AI 对仓库做了一次系统审查（R01–R15）。逐条对照源码后：

- **确认存在的问题**：首页和比较页读的是手写的扩展数据，不随项目状态变化（R02、R07）；历史引用只显示版本号，链接打开的是当前版本（R08）；同一修订上的多条审阅都算“当前”，“需要修改”会让对象从待审阅中消失（R09）；拒绝、审阅没有理由（R10）；交接材料不检查过时（R11）；授权检查缺少执行者、项目和应用策略（R12）；只沿第一个上级追溯（R13）；路线名写死在代码里（R14）。
- **样机自己的科学推断错误**（R04）：晚高峰只有校准后的误差 0.113，没有校准前的值，却被记为“校准在所有时段都改善可靠性”的反证。它只能说明晚高峰校准后误差仍偏高、限制了结论的适用范围，不能反驳“有改善”。理解测试的标准答案也沿用了这个错误。
- **审查未提到、但同类的问题**：新建路线时提示“只记录‘需要独立工作区’”，实际没有记录。

## 决定

按下面的顺序推进，替代原来的“阶段A → 阶段B → 阶段C”逐项推进：

1. **修正确性问题**（本次）：上面确认的每一项都修，并补测试。展示内容改为由项目状态生成，或带上来源版本并在过时时标出。
2. **重写研究单元的默认阅读页**：按“背景、问题、做法、结果、判断、下一步”组织，只折叠公式、代码和原始数据。与 D-006 的“太密”之间的取舍由理解测试决定。
3. **导入一段真实会话**（只读、离线）：先手工整理一份标准答案，再试自动提取，比较两者；结果用于修订合同（v1.1）和决定导航结构。
4. **然后才做阶段B**：本地数据库、事务、事件重放。服务端的权限与提案校验要重新实现为权威检查，不能直接搬用浏览器里的模拟服务。

## 暂不做

以下建议要等真实会话导入之后再定，因为在 9 个节点的虚构项目上验证不出效果：以“当前工作空间”为中心的新导航、图上的研究操作菜单、按缩放级别显示不同内容、项目复盘页。

## 约束

- 仓库是公开的。真实会话和由它生成的项目数据不得提交到仓库：放在仓库之外，或放在 `.gitignore` 排除的目录里。
- 合同 v1.0.0 的证据关系只有“支持 / 反驳”。“限制适用范围”在样机中用阅读说明的 `limitation` 和扩展字段表达，合同 v1.1 时正式补上。
