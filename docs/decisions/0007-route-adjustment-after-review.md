# D-007 外部审查后的路线调整：先修正确性，再用真实会话检验，然后做阶段B

- 状态：已采用。第1步与工作包一已于 2026-11-26 完成；第二轮审查后顺序调整为：导入真实项目 → 在真实数据上重新设计 → 阶段B（见文末）
- 日期：2026-11-26
- 相关：方案“实施阶段”表与其后的说明（“不能用大量没有界面的基础设施代替用户闭环”；工期在“完成样机与一个真实连接器后”再估）、D-002、D-006

## 背景

另一个 AI 对仓库做了一次系统审查（R01–R15）。逐条对照源码后：

- **确认存在的问题**：首页和比较页读的是手写的扩展数据，不随项目状态变化（R02、R07）；历史引用只显示版本号，链接打开的是当前版本（R08）；同一修订上的多条审阅都算“当前”，“需要修改”会让对象从待审阅中消失（R09）；拒绝、审阅没有理由（R10）；交接材料不检查过时（R11）；授权检查缺少执行者、项目和应用策略（R12）；只沿第一个上级追溯（R13）；路线名写死在代码里（R14）。
- **样机自己的科学推断错误**（R04）：晚高峰只有校准后的误差 0.113，没有校准前的值，却被记为“校准在所有时段都改善可靠性”的反证。它只能说明晚高峰校准后误差仍偏高、限制了结论的适用范围，不能反驳“有改善”。理解测试的标准答案也沿用了这个错误。
- **审查未提到、但同类的问题**：新建路线时提示“只记录‘需要独立工作区’”，实际没有记录。

## 决定

按下面的顺序推进，替代原来的“阶段A → 阶段B → 阶段C”逐项推进：

1. **修正确性问题**（本次）：上面确认的每一项都修，并补测试。展示内容改为由项目状态生成，或带上来源版本并在过时时标出。
2. **重写研究单元的默认阅读页**：按“背景、问题、做法、结果、判断、下一步”组织，只折叠公式、代码和原始数据。与 D-006 的“太密”之间的取舍由理解测试决定。
3. **导入一段真实会话**（只读、离线）：先手工整理一份标准答案，再试自动提取，比较两者；结果用于修订合同（v1.1）和决定导航结构。
4. **然后才做阶段B**：本地数据库、事务、事件重放。服务端的权限与提案校验要重新实现为权威检查，不能直接搬用浏览器里的模拟服务。

## 暂不做

以下建议要等真实会话导入之后再定，因为在 9 个节点的虚构项目上验证不出效果：以“当前工作空间”为中心的新导航、图上的研究操作菜单、按缩放级别显示不同内容、项目复盘页。

## 约束

- 仓库是公开的。真实会话和由它生成的项目数据不得提交到仓库：放在仓库之外，或放在 `.gitignore` 排除的目录里。
- 合同 v1.0.0 的证据关系只有“支持 / 反驳”。“限制适用范围”在样机中用阅读说明的 `limitation` 和扩展字段表达，合同 v1.1 时正式补上。

## 第二轮审查与工作包一（2026-11-26）

第二轮审查确认第1步的主要修正有效，但又指出 8 个具体问题；逐条写测试复现，全部存在，其中“读懂了会清空修改意见”是第1步引入的，“已拒绝的候选能被重新采用”是第1步写的状态转换漏洞。第1步“修完”的说法过头了：R07、R11、R12、R14 当时只修了主要路径。

这些问题按三个根源处理，而不是逐条打补丁：

| 根源 | 改动 |
|---|---|
| 当前状态没有优先于此前写好的说明 | 研究单元页的“下一步”以单元当前安排为准，说明里当时的建议只作参考；安排写于相关决定之前时标为可能已过时，并给出“按决定更新”的建议（不自动改写，由研究负责人确认），首页也会提醒；说明里提出的待决定事项已决定时，不再显示“需要你决定” |
| 同一类操作没有统一入口 | 新建研究单元只走一个函数（谱系、证据关系、模板说明、不变量检查一致）；“读懂了”和审阅结论互不覆盖；只有待处理的候选才能被采用；本机用户和授权从项目数据中找，所有人工操作都检查本人授权（完整的权限中间件仍留到阶段B） |
| 证据只有关系类型、没有有效性；交接材料是拼出来的 | 证据分为当前有效、需要重新核验、历史三类，只有当前有效的计入判断；找不到的来源算过时；交接材料按当前任务重建为 8 部分：目标与约束、本轮问题、已有发现及适用条件、有效决定及理由、已否定的路线及原因（含重新考虑的条件）、进度与阻塞、修改意见、下一步与完成条件 |

同时为导入真实项目做了准备：

- 项目数据改由开发服务器按名字提供，不再编译进前端；本机项目放在 `RW_DATA_DIR` 指向的仓库外目录；每个项目的本机操作分开保存。
- 新增第二个内置项目 `mini`（综述写作，没有任何扩展数据）。首页要点、路线比较在没有写好内容时由状态整理；扩展数据的各部分都可以缺省。
- 前端代码里不再写死任何夹具对象编号（有测试检查）。
- 新增 13 项连续使用场景测试，对应审查第八节的表格；测试共 67 项。

暂缓：历史版本页只覆盖 7 类对象（审查 4.7）；完整的权限中间件；真实数据提交前的自动检查（导入真实项目时与数据位置一起定）。

## 之后的顺序

1. **导入一个真实项目**：由研究负责人挑选一个持续数周、改过方向的项目，先取几十轮有实质内容的对话；先手工整理一份标准答案，再试自动提取；数据放在仓库之外。
2. **在真实数据上重新设计**：“当前工作 / 探索地图 / 知识与依据”三个视角、研究单元的阅读叙事、图上的继续 / 分支 / 比较 / 回退入口。
3. **阶段B**：本地数据库与权威的服务端校验。
