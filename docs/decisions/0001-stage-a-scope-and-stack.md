# D-001 阶段A的范围与技术栈

- 状态：已采用
- 日期：2026-11-25
- 相关：方案 §9.1、§17.2、§17.3

## 背景

方案 §17.2 规定阶段A为“可理解样机”：固定示例、首页、节点阅读、图与大纲、比较、审阅语义；通过条件是陌生读者理解任务通过，并且不接真实模型也能解释完整闭环。

## 决定

1. **技术栈与方案一致**：React + TypeScript（Vite 构建），图谱用 React Flow，层级布局用 ELK。这样阶段B可以直接沿用前端，不需要重写。
   - 候选：零依赖的静态 HTML。更快，但阶段B要重写，也用不了 React Flow 和 ELK。研究负责人选择了按规范技术栈。
   - 本机原先没有 Node，已从 nodejs.org 安装官方 LTS v26.13.1（校验 SHASUMS256），解压在 `~/.local/node`，并把 node/npm 链接到 `~/.local/bin`。
2. **仓库按 §17.3 的职责边界划分**（名称可调整，边界不变）：
   - `packages/contracts`：交接包 v1.0.0 合同原文（未修改，`npm run contracts:check` 按 MANIFEST 校验）和由 Schema 生成的 TypeScript 类型。
   - `packages/domain`：状态显示语义和不变量检查的纯函数（授权覆盖、身份、版本、成环、审阅当前性、能力降级）。阶段B的本地服务应调用同一套函数。
   - `apps/web`：页面与交互。
   - `fixtures/stage-a`：夹具生成器、生成的快照与扩展数据。
3. **没有服务端**。阶段A的“本地服务”是 `apps/web/src/data/service.ts` 中的浏览器内模拟：按 §14.4 的顺序做检查，生成新的对象修订和本地事件；投影由“夹具快照 + 本地事件”计算。所有模拟操作只存在浏览器 localStorage，界面顶部始终提示。
   - 这是样机的权宜做法，不是架构：阶段B必须由本地事务服务拥有真源，前端不得替服务端做授权决定（§17.3）。
4. **不接任何模型或 Harness**。连接能力、会话事件都来自夹具；需要模型的功能（局部提问）显示为不可用并说明原因。

## 阶段A覆盖的方案要求

| 方案要求 | 样机中的位置 |
|---|---|
| 首页自包含简报、实质变化、最大不确定性、当前工作、待关注（至多三项高亮）、最近成果、连接状态（§6.1） | 项目首页、顶部连接栏 |
| 二维分层地图，当前路径突出，历史分支可折叠，跨分支引用用不同线型和文字，“正在查看/正在执行”分开，新增记录不重排整张图，可固定位置、搜索、切换大纲（§6.2） | 探索地图 |
| 图谱的等价大纲（§6.7、AC-036） | 大纲 |
| 节点详情：固定区域、四层阅读、活动流水折叠、局部提问（无模型时降级）（§5.3、§6.3） | 研究单元页 |
| 阅读说明内容契约 C01–C10、术语先修卡、读者工具（补足背景、例子、定位实现、变化依据）（§5.2、§5.4） | 研究单元页“概览” |
| 路线比较：共同维度、未知写未知、不可比指标分区（§6.4） | 路线比较 |
| 决策与审阅：选项、依据、风险、允许的具体行动；接受/拒绝/暂缓/要求补充；授权复用；审阅与采用分开（§4.5、§6.5、§8.1） | 决策与审阅、研究单元页侧栏 |
| 成果与证据：支持与反证并列，实验反查主张，声称与实际不一致（§6.6） | 证据与成果、研究单元页“实现” |
| 历史记录回放与现在回看、从快照继续默认新建分支（§4.6、§7.5） | 快照页 |
| 能力清单与诚实降级（§12.3） | 连接与能力、“在此开展工作”“请求停止” |
| 可访问性：16px/1.6、可调字号、高对比度、键盘、焦点、不抢焦点的播报、不依赖颜色（§6.7） | 全局 |

## 不在阶段A范围内

真实服务端、SQLite、事件重放、Harness 连接、模型调用、导入流程、备份与隐私清除。这些属于阶段B及以后。
