长期科研协作工作台 v1 核心实施合同
版本 1.0.0
日期 2026-11-25

一 交付内容
core-api.yaml 是 OpenAPI 3.1 合同，domain.schema.json 是 JSON Schema 2020-12 领域合同，example-project.json 是结构合法的虚构项目快照，acceptance-cases.json 是实现后必须执行的验收场景。本目录没有运行中的服务，也没有连接任何真实科研项目。数据及hash仅为夹具，不作为实验或用户授权证据。

二 唯一真源
单一本地服务维护 SQLite。events 表为业务历史真源，所有当前实体表和索引是同一事务内生成或更新的投影。导出的JSON、JSONL和Markdown不能成为平行可修改真源。人工编辑导出文件不直接写回；未来导入必须经过解析、来源标注、候选变化和授权。原始大文件采用内容寻址、先落文件后事务引用，孤儿文件可回收。

三 版本与状态
所有实体具有稳定id和revision，Project.revision是有效研究状态与授权的语义并发版本。原始日志、会话运行状态、实验心跳与指标、候选提案、ContextBundle和ReadingBrief不增加Project.revision；这些对象可改变自身revision并产生新的event_seq。只有正式改变目标、约束、路线、已采用决定、主张评估、有效关系、研究单元状态或授权等，才增加Project.revision。不能因每条日志而使用户按钮不断409。

POST请求的expected_revision统一引用Project.revision，但用途有两类：业务命令要求与当前版本相同，冲突返回409并且不部分提交；原始采集只把该版本作为来源关联，较旧观测仍保存；派生内容把它作为固定输入快照，过时产物不能覆盖当前解释。适用于提案、授权等具体目标的操作另带expected_target_revision。创建项目使用expected_revision=0。Proposal.base_project_revision只是输入快照；提交提案本身不推进语义版本，应用时再检查当前请求版本和目标读集。Derived ReadingBrief/ContextBundle保存精确实体版本。

ResearchUnit.work_state描述工作活动。finished要求completion中记录完成条件满足或有保留的停止理由；Harness的turn/session结束不自动完成单元。一次科研工作回合可以包含多个turn、SessionBinding和ExperimentRun，按单元、分支和事件关联组织，不需要每轮创建新研究节点。Claim.assessment描述科学判断。Decision.status描述选择。ReviewRecord.status描述针对reviewed_revision的审阅，understanding_status记录用户明确报告的理解状态。SessionBinding.state描述执行会话。实验成功、节点完成、浏览页面、接受方案四者不能互相自动升级。旧审阅不删除，但目标版本改变后is_current=false。

schema_version位于导出及事件信封；实体revision是内容修订，两者不是同一层版本。Proposal.target_revision_refs集中保存命令目标及依赖对象的精确读集，服务端必须核验并补全所有实际读取的前提；不接受模型省略依赖来绕过并发检查。每条DomainCommand只传定义的目标和变更字段，不重复传项目版本。

四 图与对象
ResearchUnit是默认探索图的节点。Goal为Project字段，Claim、Evidence、Decision和ArtifactVersion是独立关联对象，不把每轮聊天或每条工具事件升级为图节点。GraphEdge是关系真源，ResearchUnit.parent_unit_ids为由continues_to入边计算的只读投影。

continues_to：ResearchUnit前驱 -> ResearchUnit后继，要求无环。
depends_on：依赖方ResearchUnit -> 前提ResearchUnit，活动依赖子图要求无环。
supports和contradicts：Evidence -> Claim；证据关系自身是可审查判断，不表示绝对真值。
supersedes：新Decision -> 旧Decision，不允许替代环；旧Decision.status=superseded并指向新Decision。
uses：ResearchUnit -> Evidence、Decision或ArtifactVersion。
produces：ResearchUnit -> ArtifactVersion。
reorganizes_to：旧ResearchUnit -> 拆分或合并后的ResearchUnit，只记录整理，不代表科研进展。
GraphEdge同时保存source_revision和target_revision。continues_to采用identity_lineage保留身份谱系；其他关系采用exact_revision，端点修订改变后currency=needs_revalidation，不自动把旧证据视为支持新结论。continues_to与reorganizes_to联合谱系不得成环；depends_on子图也不得成环。
每条边的端点必须存在且属于同项目；跨项目复用须显式导入引用，不能隐式穿透授权。分支融合要对冲突逐项提出决策，不能仅合并图边就宣称完成科学整合。

Claim、ResearchUnit中的对象ID列表用于成员关联和检索，不替代GraphEdge的精确修订证据关系。attach_evidence的reference只表示资料引用，映射为单元uses资料；ReadingBrief.background表示解释背景，不能被统计为支持主张的独立证据。

五 授权和身份
ActorRef由服务端鉴权生成。HTTP请求不允许提交actor、issued_by、created_by、approved:true等越权字段。模型仅能提出Proposal、检索或生成派生解释，不能调用applyProposal、创建Grant、替用户审阅或声明用户已读懂。人类明确的自然语言选择可以形成批准来源，但必须来自真实user消息且对应确定的提案版本；assistant转述不算。

当前用户已经明确授予的范围授权可复用，不为每次常规工作重复弹窗。Grant.application_policy区分human_only、policy_within_scope和policy_exact_proposal。HTTP apply仅允许human；服务器内部确定性applyAuthorizedProposal可在有效已有Grant下应用候选，不向模型、MCP或普通serviceToken开放。常规变化允许policy_within_scope；目标、关键假设、主线和重要选择自动应用必须policy_exact_proposal并绑定明确提案版本。活跃连接中可核实的明确user选择可生成精确授权并应用，不再要求用户重复点击。指代、身份或版本含混时只保留候选。成功后actor为service并引用grant，不能伪装human。

项目目标、关键假设、主线和重要决定变更需要与动作和对象相符的现有Grant。Decision记录accepted_at和authorization_grant_revision；之后授权过期仅限制新的动作，不追溯取消已经合法接受的研究决定。Grant不能覆盖操作系统、上游Harness或组织已有禁令。这里是应用业务边界，不能抵抗同OS身份具有无限文件权限的任意恶意进程；硬隔离另依赖操作系统与沙箱。

core-api.yaml中x-allowed-principal-kinds与security共同生效。服务Bearer令牌不等于human。用户写入需要会话、CSRF和Origin验证；所有接口还必须校验项目范围。MCP只有四种工具：project_context、project_recall、project_reading_brief、project_submit_proposal，不提供approve或任意数据库写入。

六 会话与能力
archive只导入；sidecar在原客户端旁观察；managed由工作台通过正式接口创建并管理。CapabilityManifest按实际版本、界面和探测结果给出supported/partial/unsupported/unverified。缺少或未核验的控制能力返回501，不用提示词假装控制。

正在运行的SessionBinding固定unit_id、branch_id、context_bundle_id和turn。点击另一节点只改变用户界面选中态。转向先中断旧执行并等回执，再新建绑定；旧turn迟到事件仍归旧节点。中断成功应答不等于所有子任务停止，必须核对执行终态、消息队列和远端实验。已发生的文件或网络副作用不会因中断自动回滚。

七 时间和原始来源
valid_time是知识适用区间，created_at/updated_at及Event.recorded_at是记录时间，Event.occurred_at是源报告发生时间。不同来源时钟未必一致；event_seq仅表示本服务事务提交顺序，不能冒充客观时间线。保留source_sequence与因果事件引用。exact locator需要稳定身份、内容摘要或经鉴权的用户操作；只有时间或语义匹配则必须correlated。资料缺失显示unavailable，不填造精确定位。

historical_reconstruction默认按recorded_at重放系统当时已有记录。若导入旧资料后按source_occurred_at重建过去，必须标history_label=reconstructed_history，并说明这不能确认用户当时已知的全部内容。current_valid默认包含后来反证，不能通过回到旧节点避开当前已知约束。

八 幂等与SSE
Idempotency-Key按principal+project+operation限定。相同key同内容返回原回执，不重复执行；同key不同内容返回409。适配器采集至少一次，按source instance、session与source event ID去重；同ID不同hash拒绝静默覆盖。事件与投影同事务，提交成功才推SSE。客户端保存Last-Event-ID，重连时按ID去重；游标过期返回resync_required，重新读完整状态。不存在跨所有外部工具的全局exactly-once保证。

每个事件payload.after_entities保存本次修改的完整实体新修订，before_revision_refs保存先前版本；仅有摘要或自然语言命令不足以当事件真源。raw_source_artifact_version_id关联不可执行的原始来源。event_seq持续增加，但project_revision_after可以在大量采集/派生事件中保持相同。只有event_history_scope=complete的导出声称具有完整重放日志；示例是excerpt，不用于重建完整项目。异步202回执可通过commands/{command_id}查询，不能只依赖SSE永不掉线。

九 快照
Checkpoint保存认知修订和文件清单。默认回退是从旧节点新建分支和可选worktree，保留当前文件、失败探索和后续反证。缺数据或环境时restore_readiness必须partial/knowledge_only。ContextBundle区分historical_reconstruction和current_valid，继续研究默认使用current_valid。代码commit、未提交patch、未跟踪文件、数据版本、环境、种子和产物需要分别记录；Harness自带文件checkpoint不能替代项目快照。

ExperimentRun没有配置或环境记录时，config_artifact_version_id/environment_artifact_version_id为null，capture_completeness=partial或unknown，missing_fields明确缺项。不用虚构artifact填满字段。只有capture_completeness=complete时上述引用必须存在且缺项为空；仍需验证对象可获取，不能仅凭字段非空宣称可复现。

外部成果尚未读取字节时，ArtifactVersion.sha256和byte_size允许null，并标version_pinning=metadata_only或unknown；只有本地可用且内容核验完成才为content_verified。快照不得因存在一个URL便声称版本固定和可恢复。

十 解释材料
ReadingBrief必须独立说明项目背景、当前问题、为何做、必要术语、方法、已知结果、未证明事项、实现变化、项目影响和下一步；必须带精确来源版本。摘要不能以“这”“上述方法”等缺少先行词的写法替代解释。显示专业简版时仍可展开先修知识、实现及原始证据。自动可读性检查只提供问题候选，不能把模型评分当成人已理解。

ReadingBrief与ContextBundle的generation记录模板或模型来源、模板版本、输入摘要、生成时间和后台命令。它描述生成过程，不能用来声称用户已理解，也不能替代source_revision_refs/items中的精确证据引用。

十一 扩展边界
v1已覆盖通过multipart上传或已授权路径登记资料，创建/修订主张和证据，修订/拆分/合并研究单元，修正关系及选择性融合分支。这些行为走明确DomainCommand和授权应用，不依赖开发者发明通用SQL或未经约束的JSONPatch。拆并源单元要求没有活跃执行绑定；原节点归档与原始记录保留。融合创建proposed分支，不自动设为主线；冲突决定需显式resolution或留待解决。create_claim初始unassessed；Evidence初始not_checked。已有finished单元的核心问题/完成条件变更必须显式重开或重新给出完成依据。

v1不穷举后续UI。新增导入器、地图布局、文件预览、实验跟踪、多人协作或桌面封装不得改变：单一真源、领域状态分离、用户批准权、精确来源、固定执行绑定、版本并发和明确能力降级。新增命令或字段必须提升合同版本并提供迁移与测试。未知字段默认拒绝；未知源事件先保留原始资料，不猜测执行语义。

十二 验证范围
制作时已在本地用jsonschema Draft202012Validator校验领域schema及完整示例；对OpenAPI所有内部和外部$ref进行路径、JSON Pointer解析和schema检查，并检查operationId唯一、路径参数齐全及请求无身份字段。未进行真实服务端、真实Harness或人类阅读测试。acceptance-cases.json中的用例是待实施验收要求，不能据此宣称产品已通过。

本地校验还检查API operationId与路径参数、写入请求的幂等与版本字段、示例关键跨对象引用，并实际执行5个非法结构的拒绝检查及2个缺失资料结构的合法检查。OpenAPI验证是静态结构、Schema与引用检查，未使用完整OpenAPI元规范验证器。60个验收场景是实现后的测试要求，并未针对产品逐项执行。

十三 隐私清除与可重放边界
Event.payload.after_entities可能含历史正文。删除敏感资料时，仅删除附件和追加删除标记不够，必须将历史事件正文、对象修订、索引、派生说明与备份副本纳入清除或密钥销毁范围，保留不含正文的审计元数据。已执行不可逆清除后不能再承诺恢复被删除的原文；完整重放测试适用于未清除部分，清除部分重放为已删除状态。应用必须明确报告这一例外，不能以事件不可变为由保留未授权正文。
